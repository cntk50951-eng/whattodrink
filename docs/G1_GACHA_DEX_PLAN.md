# UR-G1 扭蛋＋圖鑑 執行方案（待分析師審核）

> 狀態：grooming 定稿待審，未開工。
> 目標：把「今晚喝咩？」從一次性選酒按鈕變成可重玩的遊戲，以**留存（回訪）**為第一指標；免登錄可玩。
> 關聯：EPIC 4.0（多人酒桌遊戲，暫緩；G2 老虎機另案）、UR3.8（類別→品牌兩層）、UR A.5（`pickNextBatch`）、UR2.3（品牌目錄）、UR2.4（手繪 icon，✓）、`docs/api-architecture.md` §6／§10。

---

## 1. 需求背景與目標

### 1.1 問題
App 成功的關鍵是留人：用戶不登錄時沒有理由回來。「今晚喝咩？」目前是一次性決策工具，用完即走。

### 1.2 目標（按優先級）
1. **回訪**：給用戶明天／下週打開的理由（圖鑑進度＋每日首抽必 NEW）。
2. **傳播**：公開圖鑑鏈是分享物，訪客落地即玩（獲客）。
3. **轉化**：把「登錄認領圖鑑」變成自然的登錄動機（不做登錄牆）。
4. 守住底線：不鼓勵連續飲酒（文案「發現／收藏」，絕不用「喝過／喝遍」）、未成年人防護（年齡確認）、商標法務前置。

### 1.3 非目標（v1 明確不做）
- 集卡榜／排名（客戶端隨機＋公開＝偽造動機，v1 無服務端權威抽取）。
- 定向抽（圖鑑缺格剪影只能跳回扭蛋，不能直抽；理由：壽命＋儀式＋稀有度）。
- 交易／合成／評論；「共同 x 張」對比（v1.1，接好友機制）。
- G2 多人老虎機（另案）。

## 2. 玩法方案（v1）

### 2.1 主迴路
```
扭蛋（無限次，手指轉）→ 掉出大類（今晚喝什麼的答案，保留決策價值）
  → 品牌抽卡（無限抽，收錄去重）→ NEW 卡飛入圖鑑（翻牌揭曉動畫復用）
  → 圖鑑（全類別一律入庫；啤酒冊先行開放，他冊「已收 ×N，即將上架」）
  → 分享鏈 → 訪客看＋讚＋扭 → 登錄認領
```

### 2.2 規則（定案）
| 規則 | 定案 | 理由 |
|---|---|---|
| 扭蛋（大類）次數 | 無限 | 決策工具，設限等於趕人 |
| 品牌抽卡次數 | 無限抽，收錄去重（同一卡只收一次） | 簡單可懂；稀缺性由下面兩條保證 |
| 保底 | 連續 5 張重複 → 下一張必 NEW（N=5 寫配置，可調）；**保底只在該大類還有缺格時生效，否則順延到下次**（集滿類無法兌現時不硬給重複） | 尾段最壞情況有界；55 張全集期望 ~250 抽，無保底尾段磨人 |
| 每日首抽 | 首抽必 NEW（＋普通保底疊加） | 每次回訪的正反饋 |
| 稀有度 | 三檔，零美術成本：單 icon lane（茅台／獺祭／山崎）＝SR，其餘 N／R | 給冷門 lane 引流；重複 SR 可炫耀計數 |
| 重複卡 | 顯示「已擁有 ×N」，計入總抽數 | 計數即炫耀素材；v1 不做合成 |
| 圖鑑分冊 | 按 8 大類分冊（沿 `BEER_CATEGORIES`）；**所有卡一律入庫**，v1 只開放啤酒冊頁，他冊顯示「已收 ×N，即將上架」＋缺格剪影 | 新冊上架時用戶已有存貨＝一次回訪獎勵；空架子天天可見比缺貨更傷，先開一冊＋飢餓營銷 |
| 公開 | 鏈接公開（`/dex/:code`），免登錄可看；**不做全站廣場** | 傳播面可控（法務），廣場是給爬蟲送人頭 |
| 訪客動作 | 看＋讚（one-tap，匿名 id 去重）＋「我也來扭一個」CTA 落地即扭蛋 | 評論不做（審核成本）；對比 v1.1 |
| 年齡確認 | 公開頁＋遊戲入口一次點選＋cookie 記住，不做真驗證 | 訪客零摩擦優先；真驗證放註冊時 |
| 展示護欄 | 只展示暱稱、頭像、卡片；無性別、無收藏時間、無地點線索 | 位置關乎人身安全，收藏只關乎品味 |
| 文案護欄 | 「發現／收藏／NEW！」；禁用「喝過／喝遍／集齊開喝」 | 集齊≠喝遍，防社交壓力＋責任飲酒 |

### 2.3 數值與供給（留存模型）
- 全集期望 ~250 抽；保底把尾段單卡期望壓到 ≤6 抽。
- 內容供給＝留存天花板：建議每批 6–8 張、每 2–3 週一次「新品上架」事件；管線排期進 EPIC 4.0。
- 非啤酒 lane 各補到 3–5 icon 是開冊最低線（與 UR2.3 管線並行）。

## 3. 技術實現

### 3.1 架構原則
- **判定與演出分離**：先由純函數決定結果（可注入 `rand`，沿 `pickRandomBeerIn`／`shuffleTake` 慣例，`lib/beers.ts`），動畫只是演出。防手勢作弊＋可單測（沿 `.harness/testing.md`）。
- **抽取純本地，收錄才寫庫**：抽取零 QPS；每人寫庫 ≤ 卡片總數。v1 無需服務端權威抽取（與「無榜」自洽）。
- **零遊戲引擎**：無場景／物理／精靈需求，不引入 Phaser／Pixi／Rive／Godot（詳見 §5 選型記錄）。

### 3.2 前端結構（Next.js 現有棧，新增唯一依賴見 §3.5）
```
components/game/
  GachaMachine.tsx    # 扭蛋機：旋鈕手勢＋膠囊掉落＋開殼（Motion）
  CategoryReveal.tsx  # 大類揭曉（沿 UR3.8 lane：emoji＋名）
  BrandDraw.tsx       # 品牌抽卡＋翻牌揭曉（CSS 3D，復用酒 icon SVG）
  DexBook.tsx         # 圖鑑冊（scrapbook 排版＋缺格剪影＋進度 x/55）
  DexShareCard.tsx    # 分享卡（/dex/:code 公開頁共用）
lib/game/
  gacha.ts            # rollCategory(rand)、drawBrand(pool, seen, pity, rand) 純函數＋單測
  dex.ts              # 本地收藏狀態（localStorage，匿名 id）＋merge（登錄認領）
```

### 3.3 動畫效果明細（審核重點）
| 環節 | 效果 | 實現 | 參數初值 |
|---|---|---|---|
| 旋鈕轉動 | 手指繞旋鈕中心轉，**Pointer Events 算相對中心角度**（`setPointerCapture`＋`touch-action: none`，處理 ±180° 跳變；與地圖／底部抽屜做手勢仲裁，沿 UR1.2 教訓）；每過 30°「咔哒」＋震動（Android 從 15–30ms 真機起調，10ms 多數機器無感；iOS 無 API，跳過，套殼後走 Capacitor Haptics）＋音效（WebAudio 合成短 click，零音頻文件；**節流：最小間隔 60–80ms＋並發上限**，高速不嗡嗡） | 裸 Pointer Events＋rAF；慣性：鬆手速度→指數衰減 `ω(t)=ω₀·e^(-kt)`；**不用 Motion `drag` 線性映射**（圓周手勢語義不對） | k≈3.0，咔哒每 30°，最小有效轉速閾值防誤觸 |
| 開獎判定 | **累計轉角約 270° 即算**（慢慢轉也能出；另設「直接扭」按鈕＋首次提示動畫）→ 鎖定，調 `rollCategory`（**動畫結束後才揭曉，結果预先決定**，防「轉到想要才停」的作弊觀感） | 先算結果→播減速→揭曉 | 減速段 800–1200ms，easeOut；**全程總時長 ≤2.5s、可點擊跳過、熟練後自動加速**（無限抽，每次 3s 會膩） |
| 膠囊掉落 | 膠囊從機身掉出、彈跳兩次、開殼爆光（＋小 burst，doodle 形見慶祝粒子行） | Motion keyframes（y＋scale＋rotate） | 掉落 500ms，bounce 剛度 300／阻尼 12（初值，可調）；計入 2.5s 總預算 |
| 大類揭曉 | lane emoji 放大＋名＋「今晚就喝它」主按鈕（可選動作，非強制） | 沿現有 lane 文案 key（`catBeer` 等，三語已齊） | — |
| 品牌抽卡 | 卡背（doodle 紋）→ 點翻 → CSS 3D `rotateY` 翻出品牌 icon；NEW 卡金邊＋「NEW！」角標＋大 burst，重複卡灰階＋「已擁有 ×N」；**翻完後再飛圖鑑（兩段拆開，不與 3D 疊加）** | CSS `transform-style: preserve-3d`＋`backface-visibility`；翻轉 600ms | — |
| 飛入圖鑑 | NEW 卡縮放飛進 DexBook 對應格（**圖鑑與抽卡同頁面板形式**，免跨路由 `layoutId` 坑；或飛向固定坐標的克隆元素） | Motion `layoutId`（同頁） | 700ms；計入 2.5s 總預算 |
| 音效總則 | **默認靜音＋顯眼開關**（酒吧地鐵出聲尷尬）；iOS 需手勢內恢復 AudioContext；關鍵信息永不用聲音傳達 | — | — |
| 圖鑑冊 | scrapbook 排版：膠帶角、貼紙傾斜（±2° 偽隨機按 id 哈希，確定性 SSR 安全）、缺格剪影＋「？」（剪影點擊跳回扭蛋，**不可定向抽**） | 純 CSS＋現有 icon；傾斜用哈希非 `Math.random`（防 hydration mismatch） | — |
| 慶祝粒子 | **自繪 doodle 形狀**（星星、貼紙、酒滴，沿手繪風；默認彩紙出戲）＋z-index 沿 `z-[1100]` 教訓＋低端機降級（減量／關閉） | 自繪 canvas 形狀或定製 confetti | 計入 2.5s 總預算 |
| reduced-motion | 以上全部降級：無旋轉慣性（按鈕直接開獎）、無掉落（淡入）、無翻轉（直接切換）、無 confetti | `useReducedMotion`（Motion 內建）＋既有 C.18 口徑 | 強制 AC（§4） |
| 無障礙 | 旋鈕必須有按鈕替代操作（「直接扭」鍵盤可達）；所有動畫 `prefers-reduced-motion` 生效 | WCAG，沿項目 a11y 慣例 | 強制 AC（§4） |

### 3.4 數據與 API
```sql
-- 用戶×卡片（唯一鍵天然去重；anon_id 與 user_id 二選一有值）
user_cards(ident TEXT, card_id TEXT, obtained_at TIMESTAMPTZ,
  dup_count INT NOT NULL DEFAULT 1,
  PRIMARY KEY (ident, card_id));
-- ident = 'u:<uuid>' 或 'a:<anon-uuid>'；登錄認領時把 a: 行改寫 u:（merge，去重由主鍵保證）
-- dup_count 節流同步：重複抽到只累加本地，隨下次收錄／會話結束批量刷庫
-- （「已擁有 ×N」要上公開頁，就不能只留本地——與「情感數據」原則一致）
dex_likes(dex_code TEXT, anon_id TEXT, PRIMARY KEY (dex_code, anon_id));
-- 公開代號：建匿名身份時發 `dex_code`（短隨機，防枚舉；不可導出 user_id）
```
- `GET /dex/:code`：公開頁（SSR；**noindex＋保留 OG 分享預覽**：傳播靠分享不靠搜索，避免爬蟲收割暱稱頭像，與「不做廣場」一致）。
- `POST /api/v1/dex/collect`（登錄或匿名 id，冪等：重複收錄回 200＋`duplicate:true`；`card_id` 白名單校驗＋速率限制）。
- `POST /api/v1/dex/likes`（匿名 id 去重＋速率限制）。
- **已接受風險（文檔註明）**：收錄／點讚完全信任客戶端，可偽造 55 張全集、可刷讚；因無榜無獎勵，v1 接受（稀有度炫耀價值相應打折）；加榜加獎勵時重估→服務端權威抽取。
- 保底計數器放本地（連續重複數）；被刷只影響自己，無服務端狀態。
- 同步更新：`docs/api-openapi.yaml`＋`docs/api-architecture.md`（§10 加第三條 Realtime？圖鑑無需 Realtime——**不加**，保持兩條；讚數用回焦重讀）＋數據文檔。
- API 文檔 §9 把 consent／seen 定為永久本地——**圖鑑不屬此類**（情感價值數據，丟失＝丟 80 天心血），必須可同步，登錄認領即其實現。

### 3.5 依賴（新增唯一：motion；粒子自繪，零依賴）
- `motion`（Framer Motion 改名後，React 動畫事實標準：手勢＋layoutId＋useReducedMotion 一站式；旋鈕本體用裸 Pointer Events，見 §3.3）。
- 慶祝粒子自繪（doodle 形），不引入 `canvas-confetti`（默認彩紙與手繪風出戲）。
- 零引擎、零後端新服務（Supabase 現有表＋RLS 即可）。

### 3.6 i18n 與埋點
- 新文案走 next-intl，三語同序 parity（沿項目硬規）；key 清單開工時列（`gacha*`／`dex*` 前綴）。
- 埋點事件（匿名 id）：`gacha_spin`、`category_reveal{lane}`、`brand_draw{new:bool}`、`dex_open`、`dex_share`、`dex_visit`、`dex_like`、`dex_claim_on_login`。北極星：7 日回訪率＋圖鑑完成度分布。

### 3.7 美術資產清單（動畫的大頭，先排期）
- 扭蛋機身、旋鈕（常態／按壓態）、膠囊上下半（分層 SVG，開殼用）、出口擋板。
- 卡背（doodle 紋）、NEW 角章、缺格剪影（各冊通用一款＋問號）、各冊封面（v1 先啤酒冊）。
- 慶祝粒子三形：星星、貼紙、酒滴（自繪）。
- 全部沿 AI-SVG 管線＋手繪風；分層命名供代碼直接引用；無資產不開工動畫聯調。

### 3.8 性能預算
- 中檔 Android（Snapdragon 6 系）旋鈕跟手 60fps，掉落＋揭曉不掉幀（低端機自動降粒子＋關慣性）。
- 遊戲路由按需加載（`next/dynamic`），首屏不為遊戲買單：匿名訪客首載即留存漏斗第一步，遊戲包體積上限待實測定（初值：JS ≤150KB gzip，不含已有的 icon）。
- 圖片：icon 全是內聯 SVG，零點陣請求。

### 3.9 跨端可移植（Capacitor vs 純原生，決策見 §6）

| 路線 | 動畫代碼復用 | 代價 |
|---|---|---|
| Web（Vercel，現在） | 100% | 無 |
| Capacitor 套殼 | 基本 100%（跑 WebView，震動／推送改走原生插件） | `output:'export'`（API 路由外移，見 §5）；App Store 4.2「套殼駁回」風險，需原生能力（震動／推送／分享／定位）撐住存在理由；另有 OTA（Capgo）免審更新紅利 |
| 純原生 SwiftUI＋Compose | **0%，寫兩遍**（Motion／CSS 3D／canvas 全是網頁技術；或引入 Rive 共享一份，前提是有動畫師） | 兩個 UI 棧＋要 iOS／Android 人力；手感上限最高 |

背景：`docs/api-architecture.md` §2 架構圖的三端是 Web＋SwiftUI＋Compose 同一 API 契約（§6：yaml 即真源），§10 明確「原生殼只留選項不選型」（Capacitor／Tauri／純 PWA 三選一）。遊戲是第一個重度依賴殼決定的界面：選 Capacitor＝一次寫完，選純原生＝寫三遍（或 Rive）。

無論選哪條，現在就降移植成本（已納入本方案）：
1. **動畫參數即規格**：§3.3 的步距／k 值／時長／彈簧參數就是移植契約，原生照抄保手感一致。
2. **規則純函數＋公開測試向量**：`lib/game/gacha.ts` 配種子→輸出的固定用例，原生實現後跑同一組。
3. **DexBook／ShareCard 純展示**：數據只從 props／JSON 進。注意：套殼靜態導出無 SSR，`/dex/:code` 在 App 內只能客戶端渲染，網頁端才走 SSR（分享鏈不受影響）。

## 4. 驗收標準（AC）
- AC1：免登錄全流程可玩（扭→大類→抽卡→圖鑑→分享鏈→訪客扭），三語＋移動端豎屏。
- AC2：連 5 重複必 NEW；每日首抽必 NEW；重複只計數不重收（唯一鍵＋單測）。
- AC3：reduced-motion 下全降級（靜止替代），旋鈕有按鈕替代操作。
- AC4：公開頁只含暱稱／頭像／卡片＋年齡確認＋「我也來扭一個」；無性別／時間／地點。
- AC5：三閘綠（build／lint／單測，純函數單測沿 testing.md）；`git status` 無 v1（遊戲住 v2/新目錄或獨立路由，待定）。

## 5. 選型記錄（防以後重問）
- Phaser 4（2026-04，全新 WebGL 架構，verified）／PixiJS／Cocos：無場景物理需求，不用。
- Rive：缺動畫師＋走 AI-SVG 管線，不用；純原生那天重估。
- Godot／Unity：包體＋手機瀏覽器坑（iOS 音頻崩潰 issue 未修），不用。
- Colyseus：回合制低頻用不上；Vercel WS 仍 beta（單實例 session 級），G2 用 Supabase Broadcast＋Presence。
- Capacitor：等 G1 留存數據；代價是 `output:'export'`（API 路由外移），現在不付。

## 6. 待拍板（★＝開工阻塞；第二位分析師覆核意見已併入 §2–§3）
1. ★ 每日首抽必 NEW＋連 5 保底：接受（保底僅缺格時生效＋順延，見 §2.2）。
2. ★ v1 只開啤酒冊：接受（全類別一律入庫＋「已收 ×N，即將上架」，見 §2.2）。
3. ★ `/dex/:code`：**noindex＋保留 OG 預覽**（覆核結論，見 §3.4）。
4. ★ **Capacitor vs 純原生**：二選一（差異與代價見 §3.9；選純原生＝動畫寫三遍或引入 Rive＋動畫師）。
