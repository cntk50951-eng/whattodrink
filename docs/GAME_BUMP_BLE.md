# 大話骰「碰一碰」蓝牙协议（iOS／Android 共用）

> 目的：几部手机贴近，加入者自动加入房主已开的游戏房。iOS 与 Android 必须按本文实现，才能互相碰。
> 服务端接口见 `docs/api-openapi.yaml` 的 `bump-token`／`bump-join`。

## 角色
- **房主端（Peripheral／广播）**：房主在大厅点「碰一碰」后开始广播，离开面板或开局立即停止。
- **加入者端（Central／扫描）**：用户打开「碰一碰加入」页才开始扫描，离开页面停止。

## 常量
| 项 | 值 |
|---|---|
| Service UUID | `7A3F0E10-5C1B-4E9A-9D2E-8B6F3A4C1D70` |
| Room 特征 UUID（只读） | `7A3F0E11-5C1B-4E9A-9D2E-8B6F3A4C1D70` |
| 广播内容 | 仅 Service UUID（不放昵称、房间码、凭证） |
| 距离判定（RSSI） | 平滑后 ≥ **-52 dBm** 才算「碰」（连续 3 个采样的均值）；第二名与第一名差 < 6 dB 视为分不出，弹选择而不自动加入 |
| 扫描窗口 | 发现首个达标设备后再等 **1.2 秒** 收集其他候选，再决定 |
| 凭证刷新 | 房主每 **30 秒** 向服务器取新凭证并更新特征值（凭证 60 秒过期） |

阈值是起点，需真机调；iOS 与 Android 的 RSSI 标定不同，调整时两端各自保留系数，不改协议。

## Room 特征值（UTF-8 JSON，≤ 200 字节，一次读完）
```json
{"v":1,"t":"<bump token>","n":"阿明","c":3,"m":6}
```
- `v`：协议版本，当前 1；不认识的版本忽略该设备。
- `t`：`POST /games/rooms/{id}/bump-token` 返回的 token，当不透明串。
- `n`：房主昵称（最多 12 字，超出截断）；`c`：当前人数；`m`：人数上限。

## 找人形态（双方都还没有房间）
两人（或多人）都没开房时，加入者端打开「碰一碰加入」后**也要广播**同一个 Service，Room 特征值用找人形态：
```json
{"v":1,"t":"","n":"小美","o":"3fa91c0b7d5e2a48"}
```
- `t` 为空串（没有凭证＝不是房间），`o`＝本机随机码（16 位十六进制，**每次进入碰一碰重新生成**），`n` 昵称。
- 扫描时把 `t` 非空的当「房间」（走下面的加入流程），`t` 为空且有 `o` 的当「找人者」。
- **附近有房间就优先加入房间**（不选房主）。附近没有房间、只有找人者时：把自己和所有「够近」的找人者（RSSI 规则同上）的 `o` 放在一起，**字符串字典序最小的开房**，其余人等它。所以谁开房是随机的，两端算出同一个人。
- 被选中的一方：调现有「建房」接口开房 → 房间进大厅后立刻开始房主广播（凭证形态）。其余人扫到房间后按正常流程 `bump-join` 自动入房。
- 等不到房间（建议 20 秒）；对方从「找人」变成房间后，旧的找人内容最多缓存 1.5 秒就要重读，读失败每 1.2 秒重试：提示「对方没有开房，请再碰一次」。
- 已知限制：两端对「谁够近」的看法可能短暂不一致（信号强度不对称），极端情况会各开一个房；真机调阈值时留意。

## 加入流程（加入者端）
1. 扫描 Service UUID，收集达标设备（RSSI 规则见上）。
2. 唯一达标者 → 连接 → 读 Room 特征 → `POST /games/rooms/bump-join {token}` → 成功即入房，提示「已加入 {n} 的房」。
3. 多个达标且分不出 → 弹出候选（昵称＋人数）让用户点选，再走第 2 步。
4. 失败：400（凭证过期）→ 提示「再碰一次」；409/403 按服务端 `error.code` 显示具体原因。

## 安全与隐私
- 广播不含任何可识别信息；昵称和凭证只在连上后读到。
- 凭证 60 秒过期、不含房间码；加入后房主可踢人。
- 蓝牙权限被拒：显示说明和「去设置」，不要静默失败。
- 房主面板关闭、App 进后台（iOS）、开局：立刻停止广播。
