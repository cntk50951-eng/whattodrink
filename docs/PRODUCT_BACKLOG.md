## 1. 產品願景

大部分人都有「喝一杯」的習慣——無論是一人獨酌還是朋友小聚，無論心情悲喜，生活中總少不了那一杯酒的陪伴。

想像加班後的一個雨夜，外面下著雨，身心俱疲的你很想喝一杯，卻在啤酒、紅酒、威士忌與果酒之間猶豫不決——每一種都想嘗試，卻懶得花心思選擇，那就讓天意來決定今晚喝什麼。喝下這杯酒時，你還能記錄下此刻的心情。

再想像你走進便利店，面對滿櫃的酒款無從下手——用我們的系統，只需拍一張照片，就能自動幫你挑選合適的酒。

又或者，在一個悠閒的假日午後，你決定晚上吃烤肉，卻不知該配什麼酒——那就讓系統根據你的食物與心情，為你推薦最適合的一款。

與朋友聚會時，這款產品還能支援多人線上酒桌遊戲，讓互動與氣氛瞬間拉滿。

我們系統的核心，是一套基於個人情緒、偏好等數據，結合 AI 分析的決策引擎，能精準掌握用戶當下的狀態，做出最佳推薦。

讓選酒成為一種驚喜，讓選酒成為一種樂趣，讓飲酒的過程充滿歡聲笑語——不必糾結今晚喝什麼，只需享受這個過程。

最終，我們希望打造一個分享型社區：把飲酒時的心情記錄下來、分享出去；同時挖掘並推薦更多優質的香港本地酒吧，成為一個優質的流量入口。

**我們要做什麼**
- 優質而多元的飲酒、生活內容平台
- 優質的數據護城河
- 優秀的流量入口

**不做什麼**
- 不做專業酒類品鑑——這是一個紮根生活的平台，讓選酒飲酒成為每個普通人的樂趣
- 不做電商、零售、比價平台，不直接賣酒

## 2. 目標用戶與核心場景

**Persona**：25–35 歲香港都市年輕人，涵蓋社交型飲酒、朋友聚會、家庭小酌等場景。

**核心使用場景**：
1. 「今晚喝什麼」——獨自一人或臨時聚會，不知道該喝什麼
2. 根據食物、心情與偏好推薦酒類
3. 在便利店、超市的酒櫃前猶豫不決時，只需拍一張照片，即可讓系統協助選酒
4. 朋友聚會、破冰時的助興酒桌遊戲

## 3. EPIC

### EPIC 1.0　UI & Prototype

**UR 1.0**
作為用戶，我希望無論在筆電或手機瀏覽器上，都能看到可自適應螢幕大小的網頁，這樣切換設備時，不會因螢幕尺寸不同而影響視覺體驗。

**UR 1.1　首頁互動式 Bento Grid 框架**

作為（匿名或已登入的）用戶，我希望打開首頁就能以卡片形式看到產品的核心使用場景，並且能直接點擊卡片體驗，這樣我不需要先註冊、也不需要等待輪播，就能立刻理解並試用這個產品。

*版面規則*
- 採用 Bento Grid（非對稱卡片網格），不使用 carousel／輪播元件
- 首頁展示 3 個 demo 卡片，非等權重：
  - 主卡片（視覺權重最大）：隨機抽一杯
  - 次卡片 ×2：拍照選酒、心情推薦
- 響應式規則：桌面多欄不對稱排列；平板收攏為 2 欄；手機收攏為單欄堆疊，用戶自然向下滑動瀏覽，不自動輪播

*卡片入口交互*
- 主卡片（隨機抽一杯）：點擊後原地展開，直接顯示互動結果，匿名即可使用、無需登入
- 次卡片（拍照選酒／心情推薦）：點擊後跳轉至該功能的專注頁面，因涉及相機權限／輸入欄位，不適合原地展開

*主題與樣式*
- 所有卡片的顏色、邊框、hover／active 狀態，必須透過主題 token 讀取，不可寫死顏色值，確保用戶切換主題時卡片即時跟隨變化
- 註：多主題即時切換本身是跨頁面的基礎建設，建議另拉一個獨立 UR 追蹤主題系統本身的實作範圍，UR1.1 只負責「卡片元件要吃主題 token」這一端

*多語言*
- 卡片標題、說明文字需支援 i18n key，初期至少繁中／簡中／英文，語言字串架構需可擴展，不綁死語言數量

*無障礙*
- 尊重 `prefers-reduced-motion`：用戶關閉動態效果時，卡片展開改為無動畫的直接切換
- 每張卡片 DOM 順序須與視覺呈現順序一致，避免螢幕閱讀器／鍵盤導覽順序錯亂
- 所有主題下，卡片文字與背景對比須符合 WCAG AA（一般文字 4.5:1／大字 3:1）

*邊界情況／失敗處理（僅限首頁框架本身）*
- 主卡片（隨機抽一杯）互動時，若網路不穩導致結果無法即時返回，需有 loading 狀態與逾時提示，不可讓用戶對著空白卡片等待
- 次卡片點擊跳轉時，若目標頁面載入失敗，需有明確的錯誤提示並可返回首頁，不可白屏無反應

*範圍說明*
- 拍照選酒、心情推薦這兩個次卡片，UR1.1 只負責「點擊後正確跳轉到對應功能頁」；相機權限、麥克風權限、語音降級等交互細節，屬於各自功能頁的 UR，不在 UR1.1 驗收範圍內

*驗收標準（Acceptance Criteria）*
- AC1：三個 demo 卡片以 Bento Grid 呈現，非等權重版面
- AC2：桌面／平板／手機三種斷點下，版面可正確響應式收攏，不使用輪播元件
- AC3：主卡片可匿名點擊、原地展開、產生真實隨機結果
- AC4：次卡片點擊後可正確跳轉至對應功能頁
- AC5：切換主題時，所有卡片樣式即時同步更新，無需重新整理頁面
- AC6：切換語言（繁中／簡中／英文）時，卡片文案即時更新
- AC7：`prefers-reduced-motion` 開啟時，動畫效果被移除
- AC8：所有主題下，卡片對比度通過 WCAG AA 自動化檢測

**UR 1.2　語言與主題切換元件**

作為（匿名或已登入的）用戶，我希望語言和主題的切換方式更直覺、更符合年輕族群的使用習慣，而不是傳統的下拉選單，這樣切換的過程本身也能感受到產品的設計質感。

*語言切換*
- 桌面／手機皆採用常駐分段式按鈕（segmented control），直接顯示在頁首，不需額外點擊展開
- 初期支援：繁體中文、簡體中文、English，三個選項
- 當語言數量超過 4 個時，分段按鈕降級為「更多」入口，展開為清單／選單形式，避免橫向擠壓變形

*主題切換*
- 桌面：頁首主題按鈕（色點＋目前主題名稱）點擊後，以 anchored popover 彈出視覺化色卡選單
- 手機：同一個觸發點擊後，改以 bottom sheet 從底部滑出，不使用 anchored 彈出面板
- 色卡選單每個主題需顯示一個視覺縮圖（代表該主題的實際外觀），而非純文字描述；選中狀態需有明確的邊框與勾選圖示標示
- 色卡的版面／視覺語言，需與首頁 Bento Grid 卡片保持一致的設計語彙（沿用同一套圓角、邊框、間距規則）

*主題與樣式*
- 語言切換元件與主題切換元件本身的樣式，也必須讀取主題 token，確保切換主題時，這兩個控制項本身的外觀也能即時同步更新，不可自成一套獨立樣式

*無障礙*
- 分段式語言按鈕需支援鍵盤左右鍵切換選項，並有明確的 focus 樣式
- 色卡選單開啟時，焦點需自動移入面板內第一個可互動元素；關閉（Esc 或點擊外部）後焦點需返回觸發按鈕
- Bottom sheet 需同時支援上滑手勢關閉、點擊背景遮罩、明確的關閉按鈕三種關閉方式，不能只靠手勢
- 所有主題色卡的縮圖與文字對比，需符合 WCAG AA

*邊界情況／失敗處理*
- 語言／主題選擇結果需即時生效並記住使用者的選擇：同一次瀏覽 session 內至少要記得，登入用戶則需儲存到帳號設定，避免每次重新整理都要重選
- 若主題 token 讀取失敗（例如網路異常導致設定檔未能載入），需自動 fallback 到預設主題（Nova），不可讓頁面樣式錯亂或空白

*驗收標準（Acceptance Criteria）*
- AC1：語言切換於桌面與手機皆以常駐分段式按鈕呈現，不使用下拉選單
- AC2：語言選項超過 4 個時，自動降級為「更多」清單形式
- AC3：主題切換於桌面以 anchored popover 呈現色卡選單，手機以 bottom sheet 呈現
- AC4：色卡選單中每個主題皆有可辨識的視覺縮圖，並清楚標示目前選中的主題
- AC5：語言切換元件與主題切換元件本身的樣式隨主題 token 即時更新
- AC6：分段按鈕支援鍵盤操作與正確的 focus 管理
- AC7：Bottom sheet 可透過手勢、背景點擊、明確關閉按鈕三種方式關閉
- AC8：語言與主題的選擇會被記住，重新整理頁面後維持使用者的選擇
- AC9：主題設定載入失敗時，自動 fallback 至 Nova 預設主題
