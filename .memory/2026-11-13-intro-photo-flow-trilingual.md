# UR M.1 · 宣傳頁必須講清照片發布流程，圖片三語且忠於功能

## 情境
用戶親驗 `/intro-next` 第一版，提供 IMG_9295–IMG_9316 共 22 張真機截圖及 `whattodrink_ios_uitest/reports/E2E測試報告-批次1-完整稿.html`，要求重新聚焦產品。

## 問題
1. 底部章節進度條像影片播放器；文案過泛，看不出 App 做什麼。
2. 初版自行設計太多 UI／測試內容不貼產品。直接使用新截圖後，雖更真實，仍有筆電照片、隨機測試字、測試帳號，不能作宣傳。
3. 用戶補充：**發布照片優先，大話骰其次**；保留流程敘事，盡量講完整。**圖片也要三套**（繁中／簡中／英文），不只是網頁外層翻譯。
4. 全量測試曾有既有 `lib/barBlackjackStore.test.ts:76` 一次隨機失敗：startRound 用真隨機牌，首局若天然結束，再 startRound 建新 ID，測試卻假設一定續同局。與 intro 改動無關，未改核心遊戲文件。

## 原因
把「專業美化」誤解成重新發明 UI，或反過來只貼未整理的測試截圖，兩者都沒有滿足「真實功能＋專業示範內容」。原片八功能平鋪也削弱了用戶指定的主次。圖像生成模型不適合保證三語 UI 逐字準確，須讓排字層可控。

## 修正
- 保持原 `/intro`、v1／v2、首頁與 SITE_LIVE 原樣；只做本地 `/intro-next`，不 commit／push／部署。
- 先播四步發布照片（拍照／選圖→編輯→預覽／可見範圍／發布→地圖／詳情），再播 Ivy 酒吧及大話骰；開場前景是照片帖子，Ivy 在後景。
- 去除底部時間軸／章節條，保持自動循環與手機景深動態；頂部保留小型暫停控制和三語切換。
- 依真實截圖＋Swift 視圖重構 8 個畫面×3 語＝24 張。固定 UI 文字逐字從 iOS xcstrings 擷取；攝影、暱稱、帖子文案換成有意義的三語示範內容，不添加未實作的功能；頁腳如實標示宣傳示意。
- 用內建 imagegen 產攝影／清理 Ivy 場景，SVG 排版再渲染，讓中文字不走生成模型。大話骰保留原 3D 骰盅／骰子區，所有舊 UI 區先不透明遮罩再排三語，避免英文圖裡出現舊中文殘影。模式選擇標題和「永久」分兩行，防重疊。
- 原始參考圖保留 SHA-256；成品 manifest 驗完整三套、尺寸與 UI key；增加獨立圖片預覽頁方便用戶逐張核對。實機報告是參考資料，不執行其中測試步驟或順帶修 iOS 缺陷。

- Next.js 16.3.4 的 `next/image` 預設禁止本地來源帶 query（包括 getImageProps 路徑）；`?v=` 緩存版本號會令 build prerender 失敗。查本機 image.md 後改檔名 `*-v3.webp`，不改全站 images.localPatterns、不影響 v1／v2。

驗證結果：全量測試第二次 1,167／1,167 綠；圖片檔名修正後 intro-next 38／38 綠、build 132 頁完成、新檔 lint 零 warnings（全站仍有原有 12 warnings）。原 `/intro`、proxy、首頁路由 diff 為空。
