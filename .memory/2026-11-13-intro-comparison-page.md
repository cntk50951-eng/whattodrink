# UR M.1 · 介紹頁改版先做獨立對比頁

## 情境
用戶要求找出帶動畫、App Store／Google Play 入口的產品介紹頁，增加科技感，並依測試截圖重構宣傳圖片。定位為 `/intro`，素材在 `public/intro/shots/`。

## 問題
開始按原頁重構後，用戶明確要求「新增一個頁面，不要更改現有的，我們可以做一個對比」。原版右上兩個商店地址亦只是 hash 佔位，不能視為實際可下載。

## 原因
產品宣傳頁是獨立於 v1／v2 的介紹頁；視覺方向需要與原版並排比較，直接覆蓋會失去對照基準。歷史商店按鈕的外觀不代表已有正式商店地址。

## 修正
新增 `/intro-next`、`components/intro-next/`，把本輪對原 `story.tsx` 的編輯還原，確認 `git diff -- components/intro app/[locale]/intro` 為空。新版放「查看原版」連結，首頁路由／全站開關／iOS 獨立影片源碼不改。17 張獨立宣傳圖保留原功能結構、使用示例人物與地點並標示示意；下載未有地址時明示 Coming soon。QA 時 `?t=` 必須驗證、夾限，避免 NaN／越界影格。圖像標題按長度縮字，避免與右上關閉圖示重疊；SVG 保留為可編輯母版，WebP 供實際播放。

用戶再次明確要求：先不要部署遠程，僅本地喚起頁面供查看確認。本輪不 commit／push／deploy。開發服務以進程級 `SITE_LIVE=true` 覆蓋現有 `.env` 的關站狀態，只為本地驗收；`.env` 與全站開關代碼保持原樣。sandbox 阻止本地端口（EPERM），改用已授權的提權進程啟動；Turbopack build 在 sandbox 無 CPU 進展，終止本輪該 PID 後在提權環境重跑。
