# 2026-09-05 — UR1.7：skill 论证菜单形式＋深链双保险

## 情境
- UR1.7 顶部菜单形式初版给下拉／全屏页二选一，用户打回：
  “调用 skill 深度思考最现代最佳的实践，做多一轮思考”。
- “今晚喝什麼”菜单项用户点名要复杂方案：回地图＋飞当前位置＋
  展扇形＋自动开选酒面板，和手动终态一致。

## 问题
- 第一版只从实现成本想（下拉便宜、全屏贵），没从产品角度论证
  为什么 3 个链接不值得一个路由。
- 深链有两个坑：1）App Router 只换 searchParams 时复用 client 树，
  `useState` 初始化接不到首页内点击；2）点菜单时定位还没回来，
  单闩 effect 会把镜头那条腿吞掉（和 UR1.6 闭包过期同族）。

## 原因
- 形式问题本质是 IA 问题，不是成本问题：全屏页新增路由＋返回负担，
  还盖住核心地图；现代地图 App（Google Maps／Uber）全是顶部小菜单。
- searchParams 变化不 remount，是 App Router 基础语义，开工前就该想到。

## 修正
- design-taste 走完整流程：design read（地图 App＋涂鸦体系）→ 否决全屏页
  → 下拉但禁 shadcn 默认态（border-2＋硬阴影＋font-hand＋44px 触点）。
  skill 不是摆设，被点名就真走一遍它的流程，不要只读个标题。
- 深链状态同步固定模式：`useState(prop)` 管直达＋transition effect 管站内
  导航；多条腿各记各的闩（开面板／飞镜头分离，定位后到可重试）。
- 心情入口唯一性这种“删了就丢功能”的依赖，开工前必须 grep 确认每个
  被删入口的替代路径（本轮：扇形无心情格，菜单是唯一入口）。
