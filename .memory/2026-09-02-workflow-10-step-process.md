# 2026-09-02: 增強 workflow 為 10 步流程

## 情境

用戶明確指示把 `.harness/workflow.md` 升級為 10 步流程：
1. 理解用戶需求
2. 獨立深度思考 + 找不確定點向用戶確認
3. 調用工具（context7 等）查 API
4. 開始代碼開發
5. 編譯驗證、單元測試
6. 涉及具體功能時用瀏覽器測試
7. 發現與修正（修正走 #3-#7）
8. 紀錄 memory
9. 紀錄修改日誌
10. 確認提交

## 問題

之前的 workflow 只有簡單的「提交前檢查清單」，缺少：
- 對「不確定就問用戶」這個原則沒有強制
- 對「用工具查 API」沒有放在規範裡（容易憑印象寫過時代碼）
- 對「記憶修正」沒有綁進流程
- 對「未確認不 commit」沒有硬規則

## 原因

規範初版是事後補的（見 2026-09-01 的 unit test 條目），設計時太簡化。

## 修正

`.harness/workflow.md` 改寫為完整的 10 步流程，每步有明確 input/output 與降階條件。
`CLAUDE.md` 加入硬規則摘要（4 條 must-do），讓我下次 session 開始時直接看到。

## 學習

- 規範要隨實戰演進，初版太簡單時要敢重寫
- 「不確定就問」這條要寫進規範，否則容易假設、做出錯方向
- 「未經確認不 commit」要硬規則化，否則會偷懶直接 push
