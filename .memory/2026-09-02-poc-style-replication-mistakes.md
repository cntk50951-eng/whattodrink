# 2026-09-02: UR1.3 POC 「風格重現」的失誤清單

## 情境

UR1.3 要把 `UI style/` 目錄下的 10 種風格圖，分別做成 10 個獨立 HTML demo，每頁的畫風要跟原圖「完全一樣」。

我第一次交付的版本是用一個共用 template + 10 個 theme preset（換顏色為主），用戶直接打槍：「只有顏色的不同，完全沒有圖片中的畫風」。

## 我的失誤

### 1. 一開始就用「token swap」思維
- 直覺把這當成「theme system 的延伸」做
- 寫 10 個 token 物件（配色 + 字型 + 圓角 + 邊框）就交差
- **問題**：風格不只是顏色 token，是「整個視覺語言」，包括插圖風格、構圖、裝飾密度、線條質感

### 2. vision tool 第一次只叫 JSON 結構描述，沒強迫自己逐個元素拆解
- 第一輪 vision prompt 問的是「family / palette / typography / borders / animation」
- 拿到的是宏觀分類，沒有元素級的形狀描述
- **應該做的是**：針對每個視覺元素（啤酒杯、瓶子、label、泡沫、氣泡、裝飾）各別問「線條粗細、形狀、位置、顏色」

### 3. 沒有參考原圖就憑風格名稱腦補
- 看到「Memphis」就寫幾何圖形 + 撞色
- 看到「Woodcut」就寫黑白 + 粗線
- **問題**：風格名稱只是標籤，實際視覺要回到原圖逐個元素對齊

### 4. 缺少插圖（最大敗筆）
- 用戶原話：「尤其是啤酒杯子的線條、氣泡、啤酒瓶的 logo 這些細節」
- 我的 v1 沒有畫任何插圖，只有色塊 + emoji placeholder
- **正確做法**：每個風格的核心視覺元素（酒杯/瓶子/植物/幾何）都要 inline SVG 畫出來
- 風格不只是配色，是「這個東西的畫法」

### 5. SVG 線條太對稱、太工業
- 第一次的瓶身是完美對稱的幾何 path
- 風格是「1970s vintage」，線條應該手繪抖動、有機不完美
- **解法**：
  1. inline `<filter>` 用 feTurbulence + feDisplacementMap 加抖動
  2. 但每個 path 本身就要有手繪瑕疵（座標不對稱、控制點輕微偏移）
  3. 兩者都做才像

### 6. 背景 / 場景的「雜貨感」沒出來
- 原圖是「靜物堆疊」的氛圍：木桌 + 5 隻後景瓶子 + 吊燈 + 玻璃罐 + 紙條 + 前排小瓶
- 我只放主體（杯 + 瓶），背景留白
- **缺少「這是個小酒館的角落」的場景描寫**
- 一張海報的氛圍 = 主體 × 場景 × 裝飾密度，三者都要

### 7. 沒遵守用戶「一個一個來」的節奏
- 用戶說「一個一個來，先從第一個開始」
- 我一開始想要 10 個一次交付，產出品質都不足
- 後來才回到單一風格深耕
- **教訓**：用戶說「POC」+「一個一個」= 每個都要好，寧可慢但每個到 80 分

### 8. 每次 vision 回饋我只修部分，沒一次到位
- vision 第一次回：「缺酒瓶主視覺、線條太乾淨、缺 halftone」
- 我分 3 個 commit 改（v2、v3、v4）
- 每次只修一兩項，要 3-4 輪才達標
- **正確做法**：vision 回饋列出來的所有問題一次掃完，再交付

### 9. label 文字 / logo 細節是逐字設計的
- 原圖 label 是 "KUMCIIBI / MILLAKE / LOFTER DRY" 三行（拼字怪）
- 我用 "WHATTO / DRINK / CRAFT BREW" 通用品牌
- **應該照原圖的字串和字體風格寫**，即使字是亂拼的也照抄，這是風格的一部分

## 修正

1. **新流程：先做 vision 元素級拆解，再寫 SVG**
   - 第一輪：構圖（layout / 區塊 / 比例）
   - 第二輪：每個視覺元素的形狀 + 顏色 + 線條特徵
   - 第三輪：裝飾 + 背景 + 場景
   - 然後才開始寫 code

2. **每個風格 POC 的工作清單**
   - [ ] 看圖 1 輪整體印象
   - [ ] vision 問構圖與區塊
   - [ ] vision 問主視覺元素（杯 / 瓶 / 植物 / 幾何）的逐項拆解
   - [ ] vision 問背景裝飾
   - [ ] 寫 code（SVG 為主）
   - [ ] 截圖 + vision 對照原圖
   - [ ] 一次修完所有問題
   - [ ] 截圖 + vision 再對照，確認 80 分以上
   - [ ] 才告訴用戶「完成一個」

3. **SVG 風格要素清單（每個風格都要照這個檢查）**
   - 主視覺元素（必須 inline SVG 重畫，不能用 emoji）
   - 元素級細節：線條粗細、顏色、形狀、位置
   - 場景背景：木桌 / 牆面 / 裝飾
   - 線條質感：手繪抖動、鋸齒、平滑
   - 配色精確值
   - 文字風格（包含字串本身）
   - 質感 overlay（halftone、grain、paper noise）

4. **POC 的時程 vs 品質 trade-off**
   - 用戶說「POC」不是「prototype」也不是「production」
   - POC 重點是「PM review 用」= 視覺說服力 > 功能完整度
   - 一個 80 分的視覺 demo 比 10 個 40 分的更有決策價值

## 給未來自己的提醒

- **接到「風格重現」任務的第一步不是 coding，是 vision 拆解**
- **每個風格都有自己的「招牌元素」，必須 inline SVG 重畫**
- **配色 token 只是風格的 30%，插圖 + 線條質感 + 場景氛圍是另外 70%**
- **用戶說「完全一樣」= pixel-level 對齊，不可以「差不多」交差**
- **「一個一個來」= 每個都要到 80+ 分，寧可慢**
